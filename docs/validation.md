# 验证与发布标准

2026-10-05 已完成下面的容器与安装包检查；XF40H 真机兼容性和完整通关尚未验证。

## 已完成的验证

- 从官网获取并校验两代固定发行包；在线获取脚本和离线导入已验证。
- Ubuntu 18.04 ARM64 / GCC 7.5 / SDL2 2.0.8 编译两代程序。
- 两代各自通过世界状态撤销、存档重载、检查点恢复、损坏存档拒绝、动作映射及方屏视口回归。
- 两代各自与原作参考程序比较 1,000 帧状态轨迹，包含移动、动作和房间撤销；轨迹一致。
- 真实可执行程序运行菜单、模拟按键、正常退出、第二次启动读档；生成并人工检查方屏和 4:3 游戏截图。
- Debug 构建启用 AddressSanitizer（包含泄漏检查）及 UndefinedBehaviorSanitizer，执行回归、运行检查和原作对照通过。
- 安装 ZIP 检查 CRC、aarch64 ELF、可执行权限、素材、截图及两代文件名隔离。
- 在模拟 PortMaster 控制环境中执行两代启动脚本，验证空格路径、第二卡目录和键盘输入备用流程。
- Git 忽略规则确认原作源码、素材、下载、生成源码、二进制与 ZIP 都不进入仓库。

运行检查使用 SDL dummy 显示后端和模拟输入，不代表已测试实体控制器、KMS/DRM 或掌机性能。
原作对照覆盖固定动作序列，不能代替完整通关。安装包未公开上传、未提交 PortMaster。

复验命令：

```bash
bash scripts/build.sh aarch64
python3 scripts/package.py --local-full
python3 tests/package_check.py
```

已修复的原作适配问题：忽略负值的未激活光线索引；初始化静止阶段的移动物体绘图偏移；
旧图片解码器使用无符号位移。这些修复保持规则状态对照一致。
存档改为各代独立的版本标记及临时文件写入后替换，拒绝不完整或无效头部；不导入原作 PC 或 32 位存档。

以下是后续进一步验收要求。

## 原作行为

各代分别建立动作序列和状态预期，覆盖移动、光线能力、推物、动作解锁、跨房间与跨层行为。
用选定原作版本确认结果，不能只用移植实现自身生成的结果作为正确性依据。
优先回归容易影响解谜正确性的行为，不为目录骨架添加形式化测试。

撤销应恢复原作规定的状态范围和粒度。读档后检查点继续可用，退出前后撤销行为保持原作约定。
若修复原作缺陷，在实现和发布说明中标出差异，不悄悄更改游戏规则。

## 安装包

- 检查 ZIP 顶层结构、Linux 文件名大小写、脚本权限和解释器。
- 检查二进制架构、动态依赖与目标系统兼容性；macOS 运行成功不代表 ArkOS 兼容。
- 检查资源、许可证、元数据、截图齐全；包内没有开发机绝对路径或玩家存档。
- 单独安装一代、单独安装二代以及同时安装，均能独立运行。

## 真机验收

| 场景 | 验收要求 |
| --- | --- |
| 干净安装、断网启动 | 从 Ports 菜单启动，无需键盘或补文件 |
| ROM 位于第一张 / 第二张卡 | 脚本在设备支持的配置下找到正确目录 |
| 按键 | 移动、两个动作、撤销、菜单可用，无重复触发 |
| 小屏与不同宽高比 | 文字和关键地图可读，比例正确，关键信息完整 |
| 退出并再次进入 | 保存进度，检查点正确 |
| 运行一代再运行二代 | 两代进度、设置彼此独立 |
| 覆盖升级程序和资源 | 既有存档与设置保留 |
| 典型复杂场景 | 光线、跨房间动作正确，响应稳定 |
| 通关流程 | 两代分别至少完成一次完整通关验证 |

强制退出或断电恢复属于额外可靠性验证；发布说明应明确已验证的保存时机。
如果实现自动保存，用临时文件加替换等机制避免截断现有存档，再检查异常中断恢复。
